# 需求与 MVP 验收草案

以下范围已确认，业务阈值仍需通过授权样本校准。项目初始化验收与试妆业务验收分开记录。

| 编号 | MVP 需求                                                            | 可观察结果                                                                                                                                                                                  |
| ---- | ------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| R1   | 选择 JPEG、PNG 或 WebP 原图，检查格式、大小、解码、脸数、姿态与遮挡 | 合格照片进入工作台；错误提示可行动；拒绝无脸、多人和明显不合格输入。候选上限 15 MiB / 24 MP；分配大画布前验证尺寸，以解码结果校验扩展名声明。检测时最多识别两张脸以拒绝多人。               |
| R2   | 给出三套不同风格的规则推荐                                          | 每套有稳定 ID、名称、场景、色板、三层默认参数及原因；同一输入和规则版本可复现；低置信度时使用通用预设，肤色与脸型估计用可选信息表达。                                                       |
| R3   | 可编辑口红、眼影、腮红                                              | 每层可开关、改色、调强度；范围以受限控件为候选，不能越出安全区。原图可对比；关闭全部图层后，归一化原图的解码像素保持一致。                                                                  |
| R4   | 本机项目可保存、重开和删除；可主动导出预览图                        | 照片、草稿和偏好只写入当前项目文件夹。关掉项目后，取消旧任务并释放预览及衍生数据；重新打开可恢复已保存状态。删除只处理应用拥有的数据，不触碰导入前的原始文件。导出重编码，不复制原图 EXIF。 |
| R5   | 已分析项目可离线试妆                                                | 冷启动、选图、预览、已存关键点的项目恢复、编辑和导出均可离线。分析新照片需逐次确认后发送去元数据的缩放副本；生图另接。                                                                      |
| R6   | 可选 AI 为选中的预设生成解释                                        | 默认关闭，仅配置一家 HTTPS 供应商。用户明确触发后，只发场景、偏好枚举和预设编号，返回只作为纯文本说明。关闭、无网、失败或切换项目时，本地说明立即可用，推荐排序和渲染不受影响。             |

首版排除：登录与云同步、视频、3D、通用供应商平台、色号精准匹配和任意参考妆迁移。

## 最小用户流程

1. 新建或打开一个本机妆容项目，导入一张通过质量门禁的正面照片。
2. 选择场景与妆感，比较三套能直接预览的预设；低置信度时允许改用通用预设。
3. 调整或关闭任意一层，对比原图。可以只用本地理由，也可以主动请求一条可选解释。
4. 保存并重开草稿，或显式导出合成图。删除某张照片时同时清理其草稿和相关衍生引用。

## 验收矩阵

| 检查           | 候选通过条件                                                                                                                                                            | 证据                                                                                                                                       |
| -------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| 骨架可运行     | 干净安装依赖后，真实 Windows 窗口能显示 MakeupMirror 和中文使用说明；单一门禁包含格式、静态检查、构建与启动验收                                                         | 锁文件、Windows 验证输出和同命令 CI 配置。第一条测试在实现前因桌面程序不存在而失败。                                                       |
| 图层保真       | 禁用层对结果无贡献；所有层禁用时像素相同；有效蒙版并集外的解码像素不变；合成与导出尺寸符合约定                                                                          | 合成夹具、独立期望像素、人工区域标注、差异图。硬门禁针对确定性不变量；自然度另行盲评。                                                     |
| 照片质量       | 合格正脸通过率目标 ≥95%；另外公布不合格误放行率及原因分布                                                                                                               | 样本资格由人工先判，不从已通过模型的照片反推；记录有效数、分组和区间。                                                                     |
| 真实观感与推荐 | 「像本人」平均 ≥4/5，「自然」「推荐可用」平均 ≥3.5/5；个性化方案与通用方案对照                                                                                          | 盲评素材顺序随机化；使用拍摄者或本人和独立化妆评审；报告低分比例、分组和典型失败。ArcFace 的 0.85 只作待校准假设，权重未核许可不进入门禁。 |
| 时延和隐私     | Windows 参考机首次选择照片至有效预览 P95 <10 秒；调节 P95 ≤100 毫秒为试验目标。冷启动、热运行分报。已分析项目离线恢复；分析新照片逐次确认，其他请求按各自字段白名单验证 | 应用性能记录、临时项目目录前后快照、断网验收、网络拦截及本机假供应商请求捕获；日志无原图、文件名、密钥或脸部坐标。                         |

先用约 10 张合成夹具和 10–15 张授权照片跑通小样本。再用约 50–100 张授权照片形成盲评保留集，覆盖不同光照、肤色、妆前状态及可接受边界；拒绝样本另分层。阈值调整用开发集，保留集只做验收。这个规模用于发现问题，不足以证明人群公平性或广泛泛化。

## 交付顺序

1. 阶段 0：确认公开测试接口，初始化并验证可安装、可构建、可启动；记录版本、运行命令和已知差距。
2. 阶段 1：打通一张可控合成图和一层妆；验证几何和像素不变量，接入本机照片流程。
3. 阶段 2：扩到三层、三套推荐、对比、项目保存和导出，加入可选解释，随后跑保留集、断网与出站边界验收。
4. 阶段 3：只有观察到持续且可复现的 2D 局限，且 3D 对照显示明显收益时，才进入 FLAME/UV 方案试验。

初始化只交付阶段 0。其后建议用 4–6 周规划首个 MVP，先用 1–2 天做关键点、蒙版和本地资源装载实验；在样本授权、硬件规格和团队投入确定后重估。若该实验失败，优先收紧照片接收范围或更换分析方案，再扩大功能。
