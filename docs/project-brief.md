# MakeupMirror：项目设计草案

状态：设计基线已确认。代码目录为 `E:\Proj\makeup-face`，产品名为 MakeupMirror；用户的妆容项目目录与代码目录分开。

## 问题与价值

用户需要在实际化妆前，看见妆容配色和落点在自己脸上的效果，并能调整其中一层。成功的体验是：从一张正面照得到三套可以直接试的方案；用户能比较原图，关闭或调整口红、眼影、腮红。推荐使用场景、用户偏好和可观察到的面部信息，避免从照片推断人格、气质或族裔。

最重要的假设有两个：2D 局部叠加是否足够自然；按脸部信息匹配的方案是否比通用预设更有用。先用同一批授权照片比较「原图」「通用预设」「适配预设」，再决定增加规则复杂度或启动 3D。

## 已确认的决策

1. 首个 MVP 面向 Windows 单用户：静态正面照、三套规则推荐，口红、眼影和腮红分别可编辑。3D 留到第二阶段；视频和生成式渲染另立项。
2. 照片与妆容数据保存在用户选择的本机项目文件夹。MVP 支持一个用户配置的 HTTPS AI 供应商，默认关闭。用户触发时只发送场景、偏好枚举和预设编号。
3. 首批用手工原创的参数化预设。真实样本使用明确授权的原始照片；第三方代码、权重和纹理分别登记。
4. 使用 [proj-template](https://github.com/mutou01/proj-template/tree/0cd58426f9346e81261a197d5fd72f5b5eaee19f) 的代理入口、子系统文档和统一门禁。保留[模板许可](../TEMPLATE-LICENSE.txt)，以 `npm run verify` 统一 Windows 本地与 CI 的命令，`make verify` 为便捷入口。
5. 桌面壳采用 Go + Wails + WebView2，界面采用 TypeScript + Vite；初始化以真实 Windows 窗口和中文启动说明为验收。
6. 正式版用随包提供的 MediaPipe 在本机定位人脸。云端仅用于可选的整图生图和文字解释；整图生图逐次确认后发送缩放照片。

样本原图和同意书须独立存放，不进入 Git 或 CI。仓库只放合成测试图、评估脚本与无身份汇总数据。

## 改写后的项目任务

> 以固定提交的 `mutou01/proj-template` 初始化 MakeupMirror，保留统一验收入口和模板归属，说明必要的改动。在评审中先确认目标用户、首版边界、照片生命周期、素材来源和验收接口。交付项目设计、可追溯需求、MVP 验收矩阵、架构决策和日志/供应商的轻量设计。用授权相机原片、人工区域标注、模型卡、权重与代码许可证、模板脚本和工具运行记录核对关键假设。为初始化写一个可在公开入口观察到的失败测试，再实现最小可运行骨架、固定依赖并回归。业务实现按 2D 图层、推荐、真实样本评估逐步推进，提交第三方可复跑的命令、机器报告和盲评协议；没有实测的指标标成待校准，模型许可未核实前不得随包分发。3D 及外部模型只在存在明确收益且许可、数据边界、性能均有证据时进入后续里程碑。

> 首版做本地应用，照片、草稿和偏好保存在本机项目文件夹。MVP 的 AI 解释需用户主动开启及触发，按确认的最小数据清单出站，失败时仍能完成离线推荐和试妆。先完成设计评审和验收接口确认，再写代码。
